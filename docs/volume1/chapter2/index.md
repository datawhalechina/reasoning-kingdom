# 第2章：符号的黎明——因果的第一次建模

## 一、一个赌注

1965 年，Herbert Simon 说了一句此后被引用了近六十年的话：

> “二十年内，机器将能完成人类能做的任何工作。”

Simon 是诺贝尔经济学奖得主，是认知科学的奠基人之一，是一个极其聪明的人。他并不是在胡说。他有证据。他看见了他那个时代最令人振奋的东西：一台机器，第一次，开始像人类一样**推理**。

不是计算。是推理。

Logic Theorist——由 Newell 和 Simon 于 1956 年写出——用一组公理和推理规则，自动证明了罗素《数学原理》第二章 38 条定理中的 36 条。其中一条证明，甚至比罗素本人的版本更简洁。Simon 当时写信给朋友说：“我们发明了一台会思考的机器。”

从那一刻起，在大约三十年里，人工智能的主流范式，就建立在一个简洁到近乎优美的赌注上：

**如果你能把世界的知识表示为符号，把推理规则表示为逻辑，那么机器就能推理。**

本章的故事，就是这个赌注是如何下出的，它在哪里赢了，又为什么最终输了。

## 二、If-Then 的美学

先让我解释一下这个范式的核心是什么。

一个基于规则的推理系统，结构非常简单。它有两个部分：

**知识库（Knowledge Base）**：一组描述世界规律的 If-Then 规则。**推理引擎（Inference Engine）**：给定一个问题，沿着规则链推导出答案。

举一个经典的例子——1972 年在斯坦福构建的 **MYCIN**。MYCIN 用于诊断细菌性血液感染。它的知识库包含约 600 条规则，长这样：

```
IF  Gram stain of bacterium = positive
AND  shape of bacterium = spherical
AND  growth pattern of bacterium = clustered
THEN species of bacterium = Staphylococcus aureus (confidence 0.7)
```

推理引擎拿到一个具体病例，把已知的观测事实代入规则，一条接一条向前推，直到得出诊断和推荐治疗方案。

MYCIN 的表现令人震惊。1979 年，斯坦福做了一次盲测——把 10 个真实病例交给 MYCIN 和 5 位医学专家，然后请 8 位感染病学权威为所有答案的质量打分，但不告诉他们哪个答案来自机器。结果：MYCIN 排在所有参与者的**前列**，超过了其中几位人类医生。

那是 1979 年。

你可以理解为什么 Simon 那一代人会如此乐观。如果你能把一个领域的专家知识写成规则，机器就能成为这个领域的专家。而且它不会疲劳，不会犯粗心错误，不会因为值完夜班而判断力下降。

这个想法有一种**纯粹的美学**。世界是复杂的，但复杂的背后是规律。规律可以被显式地表达。表达之后，机器可以操作它。

问题是，“写成规则”这件事本身，比看起来要难得多。

## 三、知识瓶颈

专家系统有一个让所有人都头痛的问题，他们给它起了个名字，叫**知识获取瓶颈**（Knowledge Acquisition Bottleneck）。

:::details 知识获取瓶颈：为什么专家的知识很难写成规则？
“知识获取瓶颈”这个词说的是：**把人类专家头脑里的知识转化为计算机能处理的规则，这件事本身极其困难**。

原因有两层：
1. **专家说不清楚自己在做什么**：很多经验性判断已经自动化到了潜意识层面，专家自己都无法再把它显式地描述出来（见下方“内隐知识”）。
2. **知识是情境依赖的**：同一条信息在不同情境下含义不同，而规则系统无法优雅地处理这种依赖关系。

这是整个专家系统时代最核心的实践困难，最终拖垮了这项技术。
:::

换句话说：把专家的知识写进规则，这件事本身，就是一个几乎无法完成的任务。

你去找一个有三十年经验的外科医生，问他：“你是怎么判断病人需要手术的？”你会得到一些标准答案：看影像结果，看血液指标，看症状持续了多久。但你把这些都写进规则，发现系统的表现很糟糕。因为他没告诉你的，是三十年积累的**直觉**：病人说某句话时他皱眉的方式，两种指标同时出现时那个难以言说的“感觉”，某类病人在某个季节的特殊模式。

这些东西是真实的知识，是让他成为顶级外科医生的东西。但他说不出来。不是因为他不想说，而是因为那些知识**已经沉淀进了他认知系统的底层**——他自己都无法访问它们的显式形式。

认知科学把这种知识叫做**内隐知识**（tacit knowledge）——你知道怎么骑自行车，但你无法向一个不会骑车的人解释你在骑车时做了什么精确的力学调整。

:::details 内隐知识（Tacit Knowledge）：说不出来的那部分知识
**内隐知识**这个概念来自哲学家迈克尔·波兰尼（Michael Polanyi），他在 1958 年提出：**“我们知道的，比我们能说出来的要多。”**

典型例子：
- 骑自行车——你会骑，但你能逐帧描述你在做的每一个调整吗？
- 人脸识别——你一眼认出老朋友，但你能说出是哪些像素特征触发了这个识别吗？
- 专家判断——老中医“一看气色”，有经验的外科医生“感觉不对劲”

内隐知识的存在解释了为什么专家系统注定会遇到“知识永远写不完”的问题：最有价值的那部分专家经验，恰恰是专家自己也无法显式描述的部分。
:::

所以知识工程师（知识库的建设者）的日子非常难过。他们花大量时间和专家访谈，得到一些规则，放进系统，测试，发现覆盖不到的边界情况，回去再问，再改，再测。这个过程慢、贵，而且没有终点。

你写了 1000 条规则，发现还需要 1000 条。你写了 10000 条，发现新的案例触发了之前 1000 条都没有预料到的情况。

世界不是封闭的。规则永远写不完。

## 四、逻辑门是因果的最简形式

在继续讲专家系统的失败之前，我想在这里插入一个物理学的注脚。

当我们谈论“规则推理”的时候，我们实际上在谈论一个非常具体的物理过程。

一个逻辑门——AND 门、OR 门、NOT 门——它在做什么？给定输入，它产生确定性的输出。这是因果关系最简单、最纯粹的物理实现。

一个 AND 门：如果 A=1 且 B=1，那么输出=1。否则输出=0。这就是一条 If-Then 规则，被蚀刻在硅片上，由电子的流动来执行。

所有的专家系统，所有的逻辑推理，最底层都是这样的物理实现。因果关系在电路中被具象化：某个状态导致另一个状态，没有例外，没有概率，没有歧义。

这里有一个深刻的东西值得停下来想一想。

计算机不是在“思考”。它在做的事情是：执行一系列确定性的因果变换。每一步，输入决定输出，没有任何不确定性。麦卡锡和明斯基他们那一代人的直觉是：如果我们能把思维过程分解成足够多的确定性步骤，那么机器就能复现思维。

这个直觉在某种程度上是对的。数学证明可以被分解成符号操作的序列，而每一步符号操作都是确定性的。MYCIN 的推理是确定性的——给定相同的事实，它总是给出相同的答案。国际象棋的棋步搜索是确定性的。一大类“精确定义的问题”都可以被这样处理。

但“思维”不只是精确定义的问题的集合。

## 五、封闭世界假设

这里我们需要正式引入一个概念，因为它是本章所有问题的根源。

它叫做**封闭世界假设**（Closed World Assumption，CWA）。

:::details 封闭世界假设：你不知道的，系统认为不存在
**封闭世界假设（CWA）** 是规则型系统的默认工作方式：**凡是没有被明确记录在知识库中的事实，一律视为“不成立”或“不存在”**。

对比一下两种世界观：
- **封闭世界**：没写进去的 = 不存在（数据库式查询的逻辑）
- **开放世界**：没写进去的 = 我不知道（更接近现实）

这个假设在封闭、有界的领域（比如航班数据库）是合理的。但在开放的现实世界中，它非常危险：系统会把“我没见过这种情况”误认为“这种情况不存在”，然后自信地给出错误答案。

今天的大语言模型——在海量文本上训练、用于预测下一个词的模型——也有类似的问题：训练数据的边界，在某种意义上就是一种新形式的“封闭世界”。这个问题贯穿本书始终。
:::

在一个基于规则的系统里，你只能使用你放进去的知识。任何你没有明确说明的事情，系统都当作“不存在”或“不成立”来处理。

举个例子。你建了一个数据库，里面有你所知道的所有航班信息。有人查询“从北京到火星有没有直飞航班”。在封闭世界假设下，因为数据库里没有这条记录，系统的答案是：没有。这个答案是对的。

但是，有人查询“今天下午有没有北京到上海的航班”。数据库里没有，系统答：没有。但也许数据库只是不完整——也许有这个航班，只是你没录进去。

这两种情况，系统给出了完全一样的回答方式，但一个是正确的推断，另一个是错误的推断。封闭世界假设无法区分“明确不存在”和“不知道是否存在”。

在专家系统里，这个问题更加严重。你的规则库覆盖了医生知识的 70%。那剩下 30% 怎么办？系统不会说“我不知道”。它会沿着已有的规则往上爬，推导出一个它能推导出来的答案。这个答案可能完全错误——而系统对它充满信心。

这是一种非常危险的失效模式。

它不会困惑。它只会崩溃——而且崩溃得很自信。

## 六、MYCIN 的后代们

让我们继续故事。

MYCIN 之后，专家系统的思路被推进到几乎每一个能想到的领域。石油勘探（PROSPECTOR，1978 年——其中一个案例发现了价值约一亿美元的钼矿）。贷款审批（大量银行系统）。生产调度（DEC 的 XCON，每年为公司节省数千万美元）。

1980 年代，这是一个火热到发烫的行业。有公司在卖专家系统开发工具。有一个专门的工程师职位，叫“知识工程师”。大学开设了专门的课程。1982 年，日本政府启动了一个雄心勃勃的“第五代计算机系统”项目，目标是建造一台基于逻辑推理的超级计算机，预期十年内实现人工智能的突破。美国政府被吓到了，专门成立 DARPA 的 Strategic Computing Initiative 来应对。

听起来是不是很熟悉？每隔几十年，这种故事就会再发生一次。

然后，慢慢地，裂缝出现了。

维护成本。在一个大型专家系统中，规则之间的相互作用变得极其复杂。你修改一条规则，发现它破坏了另外三条规则的推理链。专家系统开始变得脆弱——不是在边界情况下脆弱，而是在它本来应该最强大的核心区域，因为内部矛盾而崩溃。

可扩展性。从 600 条规则扩展到 6000 条规则，系统的行为变得不可预测。知识工程师再也无法在脑子里追踪所有规则之间的交互，更不用说理解它们合并之后的整体行为了。

适应性。MYCIN 是 1972 年写的。医学在进步。新的病原体、新的检测方法、新的药物。每一次更新都需要知识工程师重新进入系统，找到受影响的规则，手动修改——同时小心不要破坏其他东西。这不是一个能够自我学习的系统。它是一个需要人类永远维护的**静态快照**。

到 1980 年代末，日本的第五代计算机项目陷入麻烦。专家系统的局限越来越清晰。1987 年，专家系统硬件市场崩溃，AI 行业进入第二次“寒冬”。

## 七、一个简单的专家系统

为了让这些不只是抽象的历史，让我给你展示一个实际的微型专家系统长什么样。

这是一个诊断“这是什么动物”的小系统——最早由 Winston 和 Horn 在 1981 年的教科书中给出，是专家系统教学中的经典案例：

你输入的事实：`["has fur", "eats meat", "is tan", "has dark spots", "has claws", "forward-facing eyes"]`

推理过程：

```
R1 fired: ['has fur'] -> is a mammal
R5 fired: ['is a mammal', 'eats meat'] -> is a carnivore
R6 fired: ['is a mammal', 'has claws', 'forward-facing eyes'] -> is a carnivore  [already known]
R8 fired: ['is a carnivore', 'is tan', 'has dark spots'] -> is a cheetah

Final conclusion: is a cheetah
```

这个逻辑是清晰的、可追溯的、可解释的。每一步推理，你都能说出它来自哪条规则。这是专家系统的一大优势——**透明度**。

但是现在，你问：如果这只动物同时有深色斑点和黑色条纹呢？

系统不知道怎么处理这种情况。R8 和 R9 都部分满足，但两条规则的结论不同——是猎豹还是老虎？结果取决于实现：有时候它报告第一个匹配的结论，有时候它陷入冲突，有时候它产生两个互相矛盾的结论。

**它不会困惑。它不会说“我不知道”。它会给你一个答案。**

而那个答案，可能完全没有意义。

## 八、为什么它失败——真正的原因

现在我要说一个比“知识永远写不完”更深的东西。

专家系统的核心假设是：**推理可以被分解成独立的、可枚举的规则，规则之间的相互作用是有限的和可预测的。**

这个假设在非常受限的领域里成立。MYCIN 面对的是细菌性感染的诊断——一个有清晰边界、有标准协议、有有限变量集合的领域。在那里，知识库接近完整，推理接近闭合。

但在开放的、现实的世界里，这个假设根本性地错误。

人类的推理不是规则系统。当你走进一个没见过的房间，你不是在访问一个关于“房间”的规则库，然后逐条过一遍。你的大脑在做的事情，是把这个新场景映射进一个内部的、高度压缩的世界模型——一个你用几十年建立、通过无数次经验不断更新的模型。这个模型是**连续的**，是**生成式的**。它可以插值，可以外推，可以在新情况下产生合理的猜测，即便这个情况在它“见过”的样本里从未出现过。

规则系统没有这个能力。规则系统是**离散的**，是**枚举式的**；它只能在它显式覆盖的区域内推理。碰到规则库的边界，它不会猜。它会崩溃。

这里有一个更深的哲学问题。1972 年，哲学家 Hubert Dreyfus 在他的《计算机不能做什么》里提出了它：人类的智能，在很大程度上依赖于我们对“什么重要”的直觉——而这种直觉是**情境性的**（situated），是我们作为生活在世界中的具身生物所积累的体验建构出来的。你无法把情境性知识抽提成脱离情境的规则，因为它本来就不以规则的形式存在。

Dreyfus 当时被 AI 社区嘲笑了。后来证明，他大体上是对的。

## 九、它留下了什么

我不想让这一章的结局听起来像一个失败故事。因为那不是全貌。

专家系统在它擅长的地方，确实很出色。规则数量有限、领域边界清晰、知识可以被完整枚举的问题——XCON 确实为 DEC 节省了数千万美元。在贷款审批系统中，如果规则写得好，偏见可以被显式地审计和纠正——这比黑盒系统内部的隐藏偏见要透明得多。医疗决策支持系统至今仍在使用某种形式的规则引擎，处理那些格式化的、规则明确的子任务。

更重要的是，专家系统时代留下了一些真正重要的遗产：

**清晰的问题分解**。把一个复杂问题分解成可以独立处理的子问题，是一种真正有价值的能力。现代软件工程仍然在做这件事。

**推理的可解释性**。你能追踪系统推理的每一步——这在今天的 AI 系统里是一种罕见的奢侈。可解释性在深度学习时代重新成为热点，而专家系统在这方面做得最好。

**知识表示理论**。围绕专家系统建立起来的知识表示理论，后来发展成了本体论、描述逻辑和语义网——这些东西至今仍在许多工业系统中运行。

:::details 本体论、描述逻辑、语义网：这三者是什么关系？
这三个词是“知识如何在计算机中被结构化”的三个层面：

- **本体论（Ontology）**：在计算机科学中，它指的是“形式化地定义某个领域的概念体系及其关系”。例如医学本体论 SNOMED 定义了“疾病”“症状”“药物”之间的层级关系。
- **描述逻辑（Description Logic）**：用来构建本体论的逻辑语言——比自然语言更精确，比完整的一阶逻辑更可计算。OWL（Web 本体语言）就基于描述逻辑。
- **语义网（Semantic Web）**：Tim Berners-Lee 提出的愿景——网页数据应该既能被人阅读，也能被机器“理解”（机器能把握数据中的语义关系）。RDF 和 OWL 是它的核心技术。

这三者构成一条从概念到应用的链条：本体论是目标，描述逻辑是工具，语义网是应用。
:::

然后，最重要的一个遗产：

**一个关于推理边界的清晰反例**。专家系统彻底地、实证地证明了：**如果推理依赖于完整的显式知识库，那么推理能走多远，就完全取决于这个库有多完整**。世界是开放的。知识库是封闭的。两者之间的张力，是任何基于规则的系统的根本极限。

这个教训的另一面，正是此后几十年 AI 研究转向的方向：不要试图把所有规则都显式写出来——而是让机器从数据中**学习**这些规律，包括所有人类无法言明的内隐知识。

这个转向并不容易，也没有完全成功。但那是下一章的故事。

## 十、一个小小的停顿

让我把这一章梳理一下。

符号 AI 和专家系统的时代给了我们一个非常干净的教训：**把世界的知识显式地表达成规则，从原则上就是一个不可能完成的任务**。不是因为我们不够努力，而是因为知识的结构本身不是规则的形式——它是情境性的、内隐的、连续的、生成式的。

逻辑门是因果关系最简的物理实现。规则系统是因果推理最直接的建模。在它们擅长的地方，它们工作得非常好。但世界比这宽广得多。

封闭世界假设是这个范式的致命缺陷：在你知道的范围内，它很强；在你知道的边界处，它会优雅地失效；而你永远不知道边界在哪里，因为你不知道自己不知道什么。

这是一个值得记住的模式——不只是关于专家系统，而是关于任何推理系统。每一个推理系统都有它自己的封闭世界边界：它显式或隐含地假设某些东西不存在，或者某些情况不会发生。当现实触碰到那个边界，推理就会以某种方式失效。

失效的方式不同，教训是一样的：**推理需要世界模型，而世界模型的边界就是推理的边界。**

第三章，我们要开始讲向量，讲连续表示空间，讲表示学习的革命。从离散符号到连续向量的这一步，是一次根本性的跨越。但这次跨越带来的新问题，可能不比它解决的旧问题少。

> 符号失败了，但它留下了一个问题：意义是什么？下一章，我们将看到向量如何给“意义”一组几何坐标。

## 符号的规模化：从专家系统到知识图谱

在结束本章之前，让我们看看符号主义的遗产如何以**知识图谱**的形式在现代 AI 中延续。

### 知识图谱：符号主义的规模化

知识图谱本质上是专家系统知识库的**规模化、结构化版本**：

- **实体**代替了专家系统的“概念”
- **关系**代替了 If-Then 规则的“条件”
- **三元组**（头实体——关系——尾实体）构成了知识的基本单元

但知识图谱面临与专家系统相似的挑战：

1. **构建成本**：需要大量人工标注或复杂的抽取算法
2. **覆盖问题**：没有任何知识图谱能覆盖所有知识
3. **动态更新**：世界在变，知识图谱需要持续更新
4. **知识表示**：如何表示模糊的、概率的、依赖上下文的知识？

### 知识图谱与大模型的对话

当前 AI 研究的一个前沿方向，是把**符号（知识图谱）与统计（大模型）结合起来**。这不是简单的替代关系——而是**互补关系**：

| 维度 | 知识图谱 | 大模型 |
|------|----------|--------|
| **知识表示** | 显式、结构化、离散 | 隐式、分布式、连续 |
| **可解释性** | 高：清晰的三元组结构 | 低：黑盒的向量运算 |
| **推理方式** | 符号逻辑推理 | 统计模式匹配 |
| **知识获取** | 人工构建/抽取 | 从文本中隐式学习 |
| **动态性** | 更新成本高 | 可通过微调适应 |

### 结合策略：RAG 与知识注入

当前主要的结合方式：

1. **检索增强生成（RAG）**：把知识图谱作为外部记忆，为大模型提供事实依据
2. **知识注入**：把知识图谱的三元组转化为训练数据，注入到大模型中
3. **符号引导生成**：用知识图谱的结构约束大模型的输出
4. **混合推理**：对确定性知识使用符号推理，对不确定性知识使用统计推理

### 深层问题：符号与统计的根本差异

这种结合面临根本性挑战：

1. **表示鸿沟**：离散符号 vs. 连续向量
2. **推理鸿沟**：逻辑演绎 vs. 概率推断
3. **知识鸿沟**：显式陈述 vs. 隐式蕴含
4. **更新鸿沟**：局部更新 vs. 全局重训

**关键问题**：知识图谱“慢而准”，大模型“快而模糊”。如何让它们**协同工作**，而不是简单地把它们粘在一起？

### 思考题：符号主义的现代复兴？

知识图谱与大模型的结合，是否意味着符号主义的某种**复兴**？还是说，这只是在统计框架下**借用**符号的形式？

一个更深的问题：如果大模型能从文本中“学习”知识，为什么我们还需要显式的知识图谱？一个可能的答案：**可解释性、可验证性、可更新性**——这些在关键应用（医疗、法律、金融）中不可或缺。

## 悬而未决

- 今天的大语言模型，是否以某种隐含的方式，重新引入了封闭世界假设？训练数据的分布，是否是一种新形式的“知识库边界”？

- 可解释性是专家系统的一个真正优势。但可解释性和正确性是一回事吗？能解释一个推理过程，不等于这个推理过程是对的。

- Dreyfus 的批评有一个核心：情境性知识无法被显式化。大语言模型是否以某种方式捕获了情境性知识？还是它们只是在做非常高维度的模式匹配？

- **符号与统计的结合**：知识图谱提供结构化知识，大模型提供泛化能力。这种结合是“1+1>2”的协同，还是“油与水”式的拼接？真正的融合需要解决哪些根本问题？

- **知识的双重表示**：同一个事实，在知识图谱中是离散的三元组，在大模型中是连续的向量分布。这两种表示如何相互验证、相互补充？当它们冲突时，应该相信谁？

## 动手试试：构建你自己的专家系统，然后看它崩溃

本章的教训是：规则写不完，边界找不到，失败来得悄无声息。只读不做，这些就只是抽象的格言。你需要亲手把它造出来，然后亲眼看着它在边界处崩溃。

### 第一步：选一个你真正了解的领域

不要选医学。不要选法律。选一个你实际有经验的领域——那种你能说出“这种情况下你应该这样做”的领域。

几个建议：

- 判断一道菜的口味风格（川菜 / 粤菜 / 日料……）
- 诊断一台电脑的常见故障（网络 / 硬件 / 软件……）
- 判断一篇文章是否值得精读（领域 / 来源 / 关键词……）
- 评估一道编程题的难度级别（简单 / 中等 / 困难）

选好之后，在纸上写下：**这个领域的最终结论有哪些？**（一个类别列表，不超过 10 个。）

### 第二步：写出你的规则库

使用本章第 7 节展示的格式，写出至少 15 条 If-Then 规则。

```python
# Rule data structure: each rule is a dictionary
# 'conditions' : list of conditions (ALL must hold to trigger)
# 'conclusion' : rule conclusion (a string)
# 'name'       : rule name, for tracing the reasoning path

# Example: a rule base for classifying cuisines
rules = [
    # --- middle-level rules: ingredient features ---
    {"name": "R1",  "conditions": ["has fish mint"],
     "conclusion": "uses Sichuan ingredients"},
    {"name": "R2",  "conditions": ["has chili pepper", "has Sichuan pepper"],
     "conclusion": "mala style"},
    {"name": "R3",  "conditions": ["has sashimi"],
     "conclusion": "uses Japanese ingredients"},
    {"name": "R4",  "conditions": ["has miso"],
     "conclusion": "uses Japanese ingredients"},
    {"name": "R5",  "conditions": ["has fermented black beans", "has steamed-fish soy sauce"],
     "conclusion": "Cantonese seasoning"},
    {"name": "R6",  "conditions": ["has ginger and scallion"],
     "conclusion": "Cantonese base"},

    # --- middle-level rules: cooking style ---
    {"name": "R7",  "conditions": ["stir-fried over high heat"],
     "conclusion": "high-heat stir-fry style"},
    {"name": "R8",  "conditions": ["steamed"],
     "conclusion": "light cooking style"},
    {"name": "R9",  "conditions": ["charcoal-grilled"],
     "conclusion": "barbecue style"},

    # --- terminal rules: conclude the cuisine ---
    {"name": "R10", "conditions": ["uses Sichuan ingredients", "mala style"],
     "conclusion": "is Sichuan cuisine"},
    {"name": "R11", "conditions": ["uses Japanese ingredients"],
     "conclusion": "is Japanese cuisine"},
    {"name": "R12", "conditions": ["Cantonese seasoning", "light cooking style"],
     "conclusion": "is Cantonese cuisine"},
    {"name": "R13", "conditions": ["Cantonese base", "Cantonese seasoning"],
     "conclusion": "is Cantonese cuisine"},
    {"name": "R14", "conditions": ["barbecue style", "uses Sichuan ingredients"],
     "conclusion": "is Sichuan-style barbecue"},
    {"name": "R15", "conditions": ["high-heat stir-fry style", "Cantonese seasoning"],
     "conclusion": "is Cantonese stir-fry"},
]
```

写的时候，注意两件事：

**a. 写中间层规则，不要只写直奔结论的规则。**

坏的写法：

```
IF has fish mint AND has chili pepper THEN is Sichuan cuisine
```

好的写法：

```
IF has fish mint THEN uses Sichuan ingredients
IF has chili pepper AND has Sichuan pepper THEN mala style
IF uses Sichuan ingredients AND mala style THEN is Sichuan cuisine
```

中间层让推理链变得可解释，也让问题暴露得更清楚。

**b. 试着从结论往回推，而不只是从条件往前推。**

问自己：“要得出‘是川菜’，最少需要哪些前提？这些前提够吗？有没有例外？”

### 第三步：实现前向链接引擎

本章已经给了你引擎的完整逻辑：

```python
def forward_chain(rules, initial_facts):
    """
    Forward-chaining inference engine.
    rules: list of rules, each with 'conditions', 'conclusion', 'name'.
    initial_facts: set of initially observed facts.
    Returns: (final fact set, reasoning trace list)
    """
    # known facts = the observed input set
    known_facts = set(initial_facts)
    reasoning_trace = []  # record which rule fired (the reasoning trace)

    # repeat inference until no new fact is added
    while True:
        new_fact_added = False  # whether a new fact was added this round

        for rule in rules:
            # check whether all rule conditions are in the known fact set
            conditions_met = all(cond in known_facts for cond in rule["conditions"])

            if conditions_met and rule["conclusion"] not in known_facts:
                # add the rule conclusion to the known fact set
                known_facts.add(rule["conclusion"])
                # record which rule fired (your reasoning trace)
                reasoning_trace.append(
                    f"fired {rule['name']}: {rule['conditions']} -> {rule['conclusion']}"
                )
                new_fact_added = True

        # stop if this round added nothing new
        if not new_fact_added:
            break

    # output: known fact set + reasoning trace
    return known_facts, reasoning_trace


# --- Example run ---
# Initial observations: the dish features on the table
initial_observations = {"has fish mint", "has chili pepper", "has Sichuan pepper", "stir-fried over high heat"}

final_facts, trace = forward_chain(rules, initial_observations)

print("=== Reasoning trace ===")
for step in trace:
    print(" ", step)

print("\n=== Final conclusions ===")
conclusions = [f for f in final_facts if f.startswith("is ")]
for c in conclusions:
    print(" ", c)
```

你不需要图形界面，不需要数据库，不需要配置文件。最简单的实现：用列表存规则，用集合存已知事实，用一个循环做推理。

### 第四步：构造三个测试用例——让一个通过，让两个失败

**案例 A：正常案例。** 一个你的规则库能完整覆盖的典型案例。输入观测，得到正确结论，推理轨迹完整。这证明系统“能工作”。

**案例 B：边界案例。** 构造一个处在两个类别之间的模糊案例——两个不同结论的前提都同时满足。观察系统的行为：它报告两个结论？选择第一个匹配的？还是悄悄给出一个错误答案？

**你的第一个问题：** 你的系统在案例 B 中的行为，是“可以接受的失败”，还是“危险的沉默失败”？这两者之间有什么区别？

**案例 C：分布外案例。** 构造一个你的规则库从未预料到的案例——比如一道同时有四川和日本食材的融合菜；或者一台故障跨越所有已知类别的电脑。

观察：系统给了你什么？它说“我不知道”了吗？还是它沿着某条最近的规则链往上爬，递给你一个看起来合理、实际上错误的答案？

**你的第二个问题：** 案例 C 的输入触发了哪些规则？这些规则本来是为哪些情况设计的？系统误用它们的方式，揭示了封闭世界假设的什么具体缺陷？

### 第五步：算一算这笔账

你写了多少条规则？它们覆盖了这个领域的多少？

估算一下：这个领域还有多少知识在你的规则之外？那些缺失的部分，是因为你不知道，还是因为你“知道却说不出来”？

**你的第三个问题（也是最难的一个）：** 如果要把你在这个领域的全部知识都转化成规则，你需要多少条？这个数字是有限的吗？

### 检验你的成果

完成这个练习后，你应该能回答：

- 你的规则库的边界在哪里——不是你猜的边界，而是你亲手撞上去的那个边界
- 系统在边界处的失败方式，是否与本章描述的“自信的错误”一致
- 知识工程师为什么说这是“一个几乎无法完成的任务”

第三条，你不需要在理论上解释清楚。你只需要在你自己的小小领域里，亲身感受一次为什么。
