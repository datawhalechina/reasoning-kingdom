## 22.1 Curry-Howard：证明即程序

第14章建立了一个形式系统：命题、推理规则、证明。第19章发现，计算与逻辑在复杂度层面是等价的：SAT 是 NP 完全的，而在命题逻辑中寻找一个证明，最坏情况下与 SAT 一样难。

但这种等价有多深？

**Curry-Howard 对应**（也叫命题即类型对应）给出答案：**深到不能再深**。

精确地说，它建立了以下对应：

| 逻辑 | 类型论 / 程序 |
|------|-------------|
| 命题 $A$ | 类型 $A$ |
| 命题 $A$ 的证明 | 类型 $A$ 的项（程序） |
| $A \to B$（蕴含） | 函数类型 $A \to B$ |
| $A \land B$（合取） | 积类型 $A \times B$ |
| $A \lor B$（析取） | 和类型 $A + B$ |
| $\bot$（假命题） | 空类型（无居民类型） |
| 假言推理 | 函数应用 |
| 演绎定理 | 函数抽象（$\lambda$ 抽象） |

这不是比喻——而是同构：逻辑推导的每一步，对应程序中的一个计算步骤；证明的规范化（化简到最简形式），对应程序的求值（运行至终止）。

::: info 兔狲教授评
很多人会在这里点头，然后继续把“逻辑”和“程序”当成两回事。同构意味着：你在逻辑里证明的每一步，就是编程语言里的一个计算步骤；你写的每一个函数，都在“证明”某个命题。如果这没让你感到震撼，你还没有真正理解这个对应在说什么。
:::

一个命题“有证明”，当且仅当它对应的类型“有程序”——对应类型是“有居民的”。**证明即程序，命题即类型，验证即运行程序。**

::: info 为什么这个对应如此震撼
在 Curry-Howard 对应之前，数学和计算机科学是两个相邻但分离的领域。对应告诉我们：它们是同一件事的两种语言。每一个数学定理都可以被理解为一个程序；每一个程序都在“证明”某个命题——证明它的输出类型可以从输入类型构造出来。这不是哲学上的相似性，而是可以用形式化手段精确验证的等价。Lean、Coq、Agda 这些证明助手正是建立在这个等价之上：写程序就是写证明，类型检查就是证明验证。
:::

## 22.2 不动点：自指的代数

第15章的哥德尔句 $G$，本质上是一个**自指构造**：$G$ 谈论自身的可证性。这个构造的数学心脏是对角化引理——一种构造“谈论自身的命题”的机制。

但自指并不只出现在哥德尔定理中。它有一个更一般的代数结构：**不动点**。

**定义（不动点）**：给定函数 $f$，若存在 $x$ 使得 $f(x) = x$，则称 $x$ 为 $f$ 的不动点。

在 λ 演算（程序的最简核心语言）中，有一个著名的不动点组合子 $Y$：

$$Y = \lambda f.\, (\lambda x.\, f\,(x\,x))\,(\lambda x.\, f\,(x\,x))$$

对任意函数 $f$，$Y\,f$ 是 $f$ 的不动点：$Y\,f = f\,(Y\,f)$。

展开来看，这个等式表明 $Y\,f$ 在“运行”自身——它把自身作为参数传给 $f$。$Y$ 组合子是递归的代数根源：每一个递归定义，本质上都是在寻找某个函数方程的不动点。

:::details Y 组合子与 λ 演算：程序的“最简核心”
λ 演算（Lambda Calculus）是阿隆佐·丘奇（Alonzo Church）与图灵同时代（1930 年代）提出的计算模型，比图灵机更紧凑：只有三类元素——变量、函数抽象（$\lambda x. \text{body}$）、函数应用（$f\,a$）。

$\lambda x. \text{body}$ 的意思是“一个接受输入 $x$ 并返回 body 的函数”。例如，$\lambda x. x+1$ 就是“加一函数”。

$Y$ 组合子是在 λ 演算中实现“递归”的工具。普通编程语言可以直接写 `def f(x): return f(x-1)`，但在纯 λ 演算中，函数没有名字，因此无法直接引用自身。$Y$ 组合子绕过了这个限制：$Y\,g$ 把 $g$ 自身作为参数传给 $g$，从而实现递归。

**这与自指有什么关系？** $Y$ 组合子是“一个寻找自身不动点的函数”——它把自指编码为纯粹的函数计算。哥德尔的对角化引理，本质上就是同一个数学结构在逻辑中的显现。
:::

用这套语言来说，哥德尔的对角化引理就是“可证性谓词”的不动点：存在命题 $G$，使得 $G \equiv \neg\mathsf{Prov}(\ulcorner G \urcorner)$——$G$ 是谓词“我不可证”的不动点。停机问题中的程序 $D$ 同样是一个不动点构造：$D$ 在输入 $D$ 上的行为，取决于 $D$ 在输入 $D$ 上的行为。

**自指、不动点与对角化，是同一个数学结构在不同语境下的不同名字。**

### 22.2.3 实操：三步展开 Y 组合子

Y 组合子的定义：$Y = \lambda f.\, (\lambda x.\, f\,(x\,x))\,(\lambda x.\, f\,(x\,x))$。

用阶乘函数的递归定义来追踪展开过程。设 $f_{\text{fact}}$ 是一个“阶乘模板”——它知道阶乘的逻辑，但不知道如何递归调用自身：

$$f_{\text{fact}} = \lambda \text{self}.\, \lambda n.\, \text{if } n = 0 \text{ then } 1 \text{ else } n \times \text{self}(n-1)$$

注意，$f_{\text{fact}}$ 的 `self` 参数是一个函数——给 $f_{\text{fact}}$ 一个计算阶乘的函数，$f_{\text{fact}}$ 就返回一个新的阶乘函数。

现在计算 $Y\,f_{\text{fact}}$ 在 $n = 3$ 处的行为。

**第0步（定义）**：
$$Y\,f_{\text{fact}} = (\lambda x.\, f_{\text{fact}}\,(x\,x))\,(\lambda x.\, f_{\text{fact}}\,(x\,x))$$

设 $w = \lambda x.\, f_{\text{fact}}\,(x\,x)$；则 $Y\,f_{\text{fact}} = w\,w$。

**第1步（展开一层）**：
$$w\,w = f_{\text{fact}}\,(w\,w)$$

把 $w\,w$ 传给 $f_{\text{fact}}$ 的 `self` 参数。展开 $f_{\text{fact}}$ 的定义：
$$f_{\text{fact}}\,(w\,w) = \lambda n.\, \text{if } n = 0 \text{ then } 1 \text{ else } n \times (w\,w)(n-1)$$

现在 $Y\,f_{\text{fact}}$ 是一个接受 $n$ 的函数，当 $n > 0$ 时调用 $(w\,w)(n-1)$。

**第2步（在 $n = 3$ 处求值）**：
$$(Y\,f_{\text{fact}})(3) = \text{if } 3 = 0 \text{ then } 1 \text{ else } 3 \times (w\,w)(2)$$

计算 $(w\,w)(2)$——这与计算 $(Y\,f_{\text{fact}})(2)$ 完全一样！因为 $w\,w = Y\,f_{\text{fact}}$。所以：
$$(w\,w)(2) = f_{\text{fact}}\,(w\,w)(2) = \text{if } 2 = 0 \text{ then } 1 \text{ else } 2 \times (w\,w)(1)$$

**第3步（继续展开）**：
$$(w\,w)(1) = f_{\text{fact}}\,(w\,w)(1) = \text{if } 1 = 0 \text{ then } 1 \text{ else } 1 \times (w\,w)(0)$$
$$(w\,w)(0) = f_{\text{fact}}\,(w\,w)(0) = \text{if } 0 = 0 \text{ then } 1 \text{ else } \ldots = 1$$

**收集结果**：
$$(w\,w)(1) = 1 \times 1 = 1$$
$$(w\,w)(2) = 2 \times 1 = 2$$
$$(Y\,f_{\text{fact}})(3) = 3 \times 2 = 6 \checkmark$$

**关键观察**：每一步，$(w\,w)$ 都在需要递归时把自身“喂”给 $f_{\text{fact}}$。$f_{\text{fact}}$ 不知道自己在调用自身——它只是收到一个函数参数 `self`，然后调用它。但 $w\,w$ 的构造保证了 `self` 就是 $w\,w$ 本身。$Y$ 组合子没有魔法——它只是把“调用自身”编码成“把一个函数应用给自身”。

**将此与哥德尔句 $G$ 对照**：
- $Y$：$Y\,f = f\,(Y\,f)$——$Y\,f$ 是 $f$ 的不动点；$Y\,f$ 的每一次展开都把自身重新传给 $f$
- $G$：$G \leftrightarrow \neg\mathsf{Prov}(\ulcorner G \urcorner)$——$G$ 是谓词“不可证”的不动点，$G$ 断言了一个关于自身可证性的命题

两者是同一个数学结构：找到一个对象，使得对它施加某种变换后的结果，在等价意义下就是这个对象本身。$Y$ 组合子以函数应用作为变换；对角化引理以可证性谓词作为变换。相同的数学结构，不同的实例。

::: info 兔狲教授评
手工展开 Y 组合子三步，你会获得一种无法从定义中得到的感觉：自指不是黑魔法，而是可以一步步追踪的机制。$Y$ 并没有“看穿”自身；它只是机械地把一个函数应用给自身。但正是这一个机械动作，创造了递归、自我意识的形式模型，以及哥德尔定理的计算版本。复杂度来自简单规则在自指下的迭代——这是全书最深的主题之一。
:::

### 22.2.5 MP 游戏：证明序列作为动力系统

假言推理（Modus Ponens，MP）是命题逻辑最基本的推理规则：有 $p$，又有 $p \to q$，就得到 $q$。

教科书给出证明的静态定义：一个有限公式序列 $\{p_1, p_2, \ldots, p_n\}$，其中每个 $p_i$ 要么是公理，要么由前面的公式经 MP 得到。这是一个静态定义——它描述的是一个已经完成的对象。

但如果我们动态地看它呢？

**游戏设定**：定义函数 $f: \mathsf{Formula} \to \mathsf{Formula}$，并要求证明序列满足 $p_{n+1} = f(p_n)$。于是证明变成了一条**轨道**：

$$p_1 \xrightarrow{f} f(p_1) \xrightarrow{f} f^2(p_1) \xrightarrow{f} \cdots$$

$f$ 的每一次应用就是一次 MP 推断：从当前公式推出下一个公式。证明序列是这个动力系统的一条轨迹。

**轨道的三种命运**：

1. **表面停止**：序列到达某个 $p_k$，使得 $f(p_k) = p_k$——形式上是一个不动点。但这只说明后继项等于自身，并不保证 $p_k$ 是真正的 QED。$p_k$ 可能是一个自指构造；“停止”只是周期为 1 的循环这一特殊情形。
2. **有限循环**：存在 $k > j$ 使得 $p_k = p_j$——轨道绕圈，没有新内容涌现。
3. **无限延伸**：序列永不终止——这对应不可判定性。没有算法能对任意给定的 $f$ 和初始公式判定轨道是否会停止。

**柯西条件与停机的微妙之处**：判断第一种命运是否“真正完成”，等价于问：序列是否成为柯西序列？

在 $\{0, 1\}$ 这样的状态空间（或任意离散空间）上，柯西条件

$$\forall \varepsilon > 0,\ \exists N,\ \forall m,n > N:\ d(p_m, p_n) < \varepsilon$$

退化为“序列最终为常数”——即最终不动。$f(p_k) = p_k$ 满足这个条件。但柯西条件只保证极限存在，并不保证极限点是“真正的答案”。

现实计算机的栈空间有限，所以我们手工施加一个截断条件——不是在极限处自动停止，而是从外部施加的停机。这个外部条件，在足够强的系统中，无法被系统自身内化。

**不动点是证明的终点**——但只有当极限点有意义时才是。当 $f(\varphi) = \varphi$ 时，$\varphi$ 在推断下“稳定”了，但它在何处稳定，需要外部验证。

这不只是比喻。对角化引理说：对任意公式 $A(x)$，存在句子 $\varphi$，使得 $\varphi \leftrightarrow A(\ulcorner \varphi \urcorner)$。把 $A$ 读作某种“推断变换”，$\varphi$ 就是该变换的不动点——它谈论自身，并在变换下保持不变。哥德尔句 $G \equiv \neg\mathsf{Prov}(\ulcorner G \urcorner)$ 就是变换“不可证”的不动点。

**Curry-Howard 的视角**：在 CH 同构下，公式对应类型，证明序列对应程序的归约序列，$f$ 对应类型上的函数 $F: \mathsf{Type} \to \mathsf{Type}$。不动点 $f(\varphi) = \varphi$ 对应递归类型 $F(T) \cong T$——例如，自然数 $\mathsf{Nat} \cong 1 + \mathsf{Nat}$ 就是 $F(T) = 1 + T$ 的不动点。

MP 游戏把三件事统一在同一个框架里：**证明的结构、动力系统的轨道、递归类型的不动点**。它们是同一个数学对象在逻辑、分析、类型论三种语言中的不同读法。

::: info 兔狲教授评
这个游戏的真正危险在第三种命运：无限延伸的轨道。你无法从外部判断一条轨道是否会停止——这不是因为你的计算能力不够，而是因为它在原则上不可判定。每当你写下一个证明，你实际上是在声称：这条轨道会停止，而且会停在我希望的地方。在足够强的系统中，这个声称无法被系统自身验证。
:::

### 22.2.6 代码中的 MP 游戏

这些轨道足够小，可以直接运行。下面的程序展示了轨道的全部三种命运——表面停止、有限循环、无限延伸——然后是柯西陷阱，最后是镜子的一个微缩版：哥德尔句作为变换“不可证”的不动点。

```python
#!/usr/bin/env python3
"""
mp_game.py -- the MP Game of Chapter 22: proof sequences as orbits.
Book reference: The Reasoning Kingdom, Volume 2, Chapter 22, Section
22.2.5 "The MP Game: Proof Sequences as Dynamical Systems."

A proof is usually a finished object: a finite sequence of formulas. The
MP game reads it dynamically: p_{n+1} = f(p_n), one modus ponens per
step, and a proof becomes an orbit of a dynamical system. An orbit has
exactly three fates -- and this program runs all three, plus the two
subtleties the book warns about:

  1. apparent stopping:  f(p) = p, but is p a TRUE QED?
  2. finite cycle:       no new content ever appears;
  3. infinite extension: the orbit never ends (undecidable, in general);
  4. the Cauchy trap:    a converging sequence whose limit point is not
                         where the transformation rests;
  5. the mirror:         the Goedel sentence as a fixed point of the
                         transformation F(phi) = "not provable(phi)",
                         built here as a tiny self-referential program
                         (Chapter 15's companion script runs the full
                         numbering machinery; this is the miniature).

Run:  python3 mp_game.py
"""


def orbit(f, x0, n):
    """The first n+1 points of the orbit x0, f(x0), f(f(x0)), ..."""
    out = [x0]
    x = x0
    for _ in range(n):
        x = f(x)
        out.append(x)
    return out


def demo():
    print("=" * 70)
    print(" THE MP GAME -- proof sequences as dynamical systems")
    print(" The Reasoning Kingdom, Volume 2, Chapter 22 (Sec. 22.2.5)")
    print("=" * 70)

    # Fate 1: apparent stopping.
    f1 = lambda x: x if x <= 0 else x - 1
    print("\nFate 1 -- apparent stopping:  f(x) = max(x-1, 0), start at 5")
    print("  orbit:", orbit(f1, 5, 8))
    print("  f(0) = 0, a fixed point. But 'stopping' only says the")
    print("  successor equals itself -- it does not guarantee 0 is a TRUE")
    print("  QED. Apparent stopping is a cycle of period 1.")

    # Fate 2: finite cycle.
    f2 = lambda x: (x + 1) % 3
    print("\nFate 2 -- finite cycle:  f(x) = (x+1) mod 3, start at 0")
    print("  orbit:", orbit(f2, 0, 7))
    print("  round and round; no new content ever emerges.")

    # Fate 3: infinite extension.
    f3 = lambda x: x + 1
    print("\nFate 3 -- infinite extension:  f(x) = x+1, start at 0")
    print("  orbit (first 8 points):", orbit(f3, 0, 7))
    print("  it never terminates. And for an arbitrary f, no algorithm")
    print("  can decide whether the orbit will ever stop -- that is")
    print("  undecidability in principle, not slow hardware.")

    # The Cauchy trap.
    print("\nThe Cauchy trap:")
    print("  sequence p_n = 1/n is Cauchy and converges to 0,")
    print("  but under the transformation f(x) = x + 1, f(0) = 1.")
    print("  the limit exists; the transformation does not rest there.")
    print("  The Cauchy condition guarantees the limit EXISTS -- not that")
    print("  the limit point is the TRUE answer.")

    # The mirror: fixed point of "not provable".
    THEOREMS = {"T1", "T2"}   # a toy provability predicate over strings

    def provable(s):
        return s in THEOREMS

    q = "q = %r; content = not provable(q %% q)"
    G = q % q
    scope = {"provable": provable}
    exec(G, {"__builtins__": {}}, scope)
    print("\nThe mirror -- G as a fixed point of F = 'not provable':")
    print(f"  G = {G}")
    print(f"  what G says, computed: {scope['content']}")
    print(f"  provable(G) = {provable(G)}")
    print("  so G <-> not provable(G): G is a fixed point of the")
    print("  transformation F(phi) = not Prov(<<phi>>). The diagonalization")
    print("  lemma in Chapter 15 is the same fixed point, grown to full")
    print("  arithmetic; the miniature here shows its shape.")

    print("=" * 70)


if __name__ == "__main__":
    demo()
```

## 22.3 依赖类型：命题作为对象

Curry-Howard 对应在简单类型论中成立。但如果我们把类型系统变得足够强——允许类型依赖于值——会发生什么？

依赖类型允许这样的表达：类型 $\mathsf{Vec}(A, n)$ 表示“元素类型为 $A$、长度为 $n$ 的向量”，其中 $n$ 是一个具体的自然数，而不是类型变量。这个类型的“居民”（程序）就是所有长度恰好为 $n$ 的向量。

:::details 依赖类型：让类型携带“证明”（前人工作：Martin-Löf, 1975）
在普通编程语言中，类型和值是分离的：`int` 是类型，`42` 是值，类型并不知道具体的值是什么。

依赖类型打破了这种分离：**类型可以依赖于值**。

例子：
- 普通类型：`Vec<int>`（整数向量，长度未说明）
- 依赖类型：`Vec<int, 5>`（恰好 5 个整数的向量；长度被编码进类型）

**为什么有用？** 因为更精确的类型 = 更强的编译期检查。如果函数签名是 `concat : Vec<A, m> -> Vec<A, n> -> Vec<A, m+n>`，编译器会自动验证拼接后的长度是正确的——不需要运行时检查，越界不可能发生。

**与 Curry-Howard 的关系**：在依赖类型中，“$\forall x. P(x)$”（对所有 $x$，$P(x)$ 成立）对应 $\Pi$-类型（对每个 $x$，一个类型为 $P(x)$ 的证明）。写一个程序 = 构造一个证明。这正是 Lean/Coq/Agda 这类系统得以可能的原因：你在用一种编程语言写数学证明。
:::

在依赖类型下，Curry-Howard 对应扩展到一阶逻辑：

| 一阶逻辑 | 依赖类型 |
|---------|---------|
| $\forall x.\, P(x)$ | $\Pi$-类型：$\prod_{x : A} P(x)$（一个把每个 $x$ 映射到 $P(x)$ 的证明的函数） |
| $\exists x.\, P(x)$ | $\Sigma$-类型：$\sum_{x : A} P(x)$（一个 $x$ 与 $P(x)$ 的居民组成的配对） |

依赖类型系统（如 Martin-Löf 类型论）实现了数学的一个古老梦想：数学对象的构造与数学命题的证明，在同一种语言中统一处理。证明一个命题，就是构造一个具有对应类型的程序；构造一个数学对象，就是写出对应类型的一个居民。

这不是形式上的把戏，而是一种深刻的统一：数学与计算、命题与数据、证明与程序——在足够精确的语言中，它们是同一件事。

## 22.4 推理系统推理自身：边界重现

现在来到本章最核心的问题。

一个推理系统——无论是形式逻辑系统、学习算法，还是大语言模型——一旦它足够复杂并开始推理关于自身，第15章的模式就不可避免地出现。

**在形式系统层面**：哥德尔定理说，任何足够强的一致系统都拥有它无法证明的真命题（包括关于自身一致性的命题）。把 $G$ 加入公理，你会得到一个更强的系统，但这个更强的系统有自己的 $G'$。这个层级没有顶端。

**在学习系统层面**：第21章的结论是，一个学习系统的归纳偏置无法从数据内部确定——它是外部输入。一个学习系统无法从自己的训练数据中推断自己的归纳偏置是否合适，正如一个形式系统无法从自身的公理中证明自身的一致性。

::: info 兔狲教授评
把这句话读两遍。这不是说归纳偏置很难选择；而是说，从原则上讲，数据无法告诉你，你的归纳偏置是否合适——正如一个形式系统无法从内部证明自身的一致性。第21章与第15章之间真正的联系就在这里：学习的盲点与逻辑的不完备性，是同一个结构性限制的两种语言。
:::

**在大语言模型层面**：这是前沿，也是最未解决的问题。通过训练，大语言模型获得了语言结构的某种内部表示。这种表示是否包含“推理规则”的某种近似？当模型“推理”自己的推理过程时（例如思维链），它在做什么？

::: info 关于 Transformer 的一个形式猜想
研究界讨论的一个非正式猜想：Transformer 的注意力机制，在足够的规模与足够的训练下，实现了某种**隐式因果推断**——通过在上下文中选择相关位置，它执行了一种近似的条件独立性测试，这与第18章的 d-分离具有结构性相似。这不是一个被证明的定理，而是一个需要精确数学刻画的猜想。如果它在某种意义上成立，那么大语言模型就不只是模式匹配器，而是在执行某种近似的因果推断——这个结论将深刻重塑我们对 AI 推理能力的理解。但“在某种意义上”是一个很大的逃生舱；现有的理论工具还无法把这个猜想变成定理。
:::

## 22.5 涌现：当量变引发质变

自指与不动点解释了“系统推理关于自身”的代数结构。但还有另一个现象，在复杂系统中广泛存在，而且更难形式化：**涌现**。

涌现说的是：当部分足够多、相互作用足够丰富时，系统会展现出任何单个部分都不具备、也无法从部分的简单求和中预测的性质。

在大语言模型的训练实践中，涌现已经被观察到：当模型规模越过某个阈值时，某些能力（如算术推理、多步推理）会突然出现，而在更小的模型中完全不存在。这些“突然出现”的能力被称为涌现能力。

### 涌现的三个层次

涌现不是单一现象；它至少发生在三个层次上，每个层次对应不同的理论工具。

**第一层：组合涌现**。简单的原子组合出新的行为能力，即使没有任何单个原子独自具备这种能力。水分子由氢和氧组成——氢和氧各自都不“湿”，但组合起来就获得了“湿”这一宏观性质。这是涌现最基本的形式，相变理论可以大致描述它——在临界点附近，系统的行为发生剧烈变化。

**第二层：计算涌现**。图灵机的单条规则（$\delta$ 函数）极其简单——根据当前状态和读到的符号，决定下一个状态、要写入的符号以及磁头的移动方向。你无法从单条规则中看出它能做微积分、下棋或写诗。但“通用图灵机”不过是一个简单的 $\delta$ 加上一条长长的纸带。计算能力是涌现的——它不属于任何单条规则，而是从规则 + 无限纸带 + 足够时间的组合中产生的。

**第三层：表示涌现**。在大语言模型中，数十亿参数经过训练后产生的能力（如类比推理、情感识别、代码生成）不是任何单个参数的功能，也不在设计者的计划之中。训练目标（下一个 token 预测）不包含“理解情感”或“写代码”的明确指令——但这些能力在足够大的规模上显现出来。

### 问题：是否存在涌现的理论？

但涌现在形式理论中极难处理。它不是一个可以被精确定义的数学概念——至少，现有的数学工具还不够。我们有描述，没有解释；有观察，没有预测。

信息论提供了一些线索。涌现可以被理解为：系统的总描述长度短于其各个部分的描述长度。一团气体由 $10^{23}$ 个分子组成，但它的状态完全由几个宏观变量（温度、压强、体积）描述。描述长度从 $10^{23}$ 降到 3——这是涌现的“信息压缩”面孔。但如何从部分的相互作用中推导出这种压缩描述，目前尚无一般理论。

动力系统理论提供了另一种视角：涌现对应相变——当某个参数越过某个临界值时，行为发生剧烈而质的变化。这种视角对物理系统具有解释力，但对于神经网络的涌现（能力随规模增长而突然出现），目前还没有精确的预测框架。

::: info 涌现是真实的现象，还是测量的幻觉？
有研究者指出：所谓的“涌现”，可能部分地是测量方式的产物。如果用连续的（而非离散的）性能指标来衡量，一些被认为突然涌现的能力实际上是在平滑增长的——只是在某个阈值处，平滑增长越过了任务所要求的最低能力门槛，从而被观察者注意到。这并不否认涌现的存在，但要求更精确的刻画：性能曲线是真的存在不连续点，还是我们的测量工具引入了虚假的不连续？目前尚无共识。
:::

## 22.6 下卷的边界，也是开口

从第14章到第22章，这条路是这样的：

从形式系统的基础，到一致性与完备性的极限，到对资源敏感的线性逻辑，到概率对真值的扩展，到因果推断对干预的形式化，到复杂度理论对推理代价的几何刻画，到启发式的形式契约，到学习作为逆推断，最后到自指与涌现。

每一章都是被前一章留下的问题逼出来的。每一章的结尾都留下一个问题，而那个问题让下一章成为必然。

沿着这条路，我们触及了几个边界：

- 哥德尔边界：足够强的系统拥有无法从内部看见的真命题。
- 图灵边界：某些问题原则上无法被任何算法回答。
- 复杂度边界：某些问题原则上无法被高效解决。
- 归纳偏置边界：学习系统无法从内部确定自己的归纳偏置是否合适。

这些边界不是障碍，而是地图。它们告诉我们：在推理这件事中，哪些地方是人类和机器都无法抵达的，哪些地方可以抵达但代价高昂，哪些地方可以用近似换取可行性。

最后，有一个问题，这本书没有回答，也无法回答：

**AI 系统目前展示的推理能力，在这张地图上处于什么位置？**

它已经走了多远，它的边界在哪里，它是否在逼近某些形式理论的边界，还是在完全不同的地方工作？这不是一个用现有工具就能回答的问题——不是因为问题不重要，而是因为我们还没有足够精确的语言来陈述它。

建立这样的语言，是接下来几十年的工作。

## 22.7 从逻辑到动力学：三个遗留问题

MP 游戏给了我们一个新视角：证明序列 $\{p_1, p_2, \ldots, p_n\}$ 是一条轨道，$f: \mathsf{Formula} \to \mathsf{Formula}$ 是演化算子，$p_{n+1} = f(p_n)$。

一条轨道有三种命运：有限停止（不动点）、有限循环、无限延伸。

但这个游戏留下了三个逻辑工具无法回答的问题：

**问题一：轨道停在哪里？**

不动点 $f(\varphi) = \varphi$ 存在，但从任意初始公式 $p_0$ 出发，系统最终会收敛到哪个不动点？逻辑只告诉我们不动点存在，不告诉我们吸引的方向。这是一个动力学问题。

**问题二：收敛的能量是什么？**

如果轨道确实收敛，就一定存在某个单调递减的量——某种“能量”。逻辑中没有能量的概念。但如果我们把信念空间 $\mathcal{P}$ 看作一个动力系统的状态空间，能量函数就自然浮现出来。

**问题三：能量从何而来？**

传统做法是手工猜测一个能量函数，并验证它递减。但如果我们已经观测到系统收敛到某个先验锚点 $A$，能不能反过来——从收敛行为推导出能量函数，而不是去猜它？

这三个问题里，前两个在第12章已经有了严格答案：永霖定理把收敛方向钉在先验锚点 $A$，能量面就是切空间上的 KL 散度，压缩映射保证递减。第三个问题——从收敛行为反推能量函数——是逆问题的提法；在本书里不必反推，因为训练目标已经给出了能量面。真正剩下的定量问题是：系统以多快的速率回到 $A$？这个速率能不能解释涌现？这是第23章的入口。

::: info 兔狲教授评
MP 游戏是逻辑与动力学之间的渡船。在逻辑这一岸，我们问“证明存在吗？”；在动力学那一岸，我们问“系统去哪里？”。不动点是两岸共享的地标——在逻辑中它是证明的终点，在动力学中它是吸引子。渡过去，你会发现那个吸引子有一个名字：永霖极限。
:::

## 悬而未决

**Curry-Howard 对应能延伸到多远？** 目前，这个对应在简单类型论和一阶逻辑层面是精确的。高阶逻辑（二阶逻辑、高阶逻辑）、模态逻辑和线性逻辑（第16章）都有不同形式的 Curry-Howard 对应，但精确程度和完备程度各不相同。是否存在一个统一的框架，把所有形式逻辑系统都纳入“命题即类型”的视角？这是同伦类型论（Homotopy Type Theory，HoTT）试图回答的问题，但 HoTT 本身仍在发展之中。

**是否存在关于涌现的数学理论？** 复杂性科学、相变理论和信息论各自提供了对涌现的部分刻画，但没有一个统一的、可预测的涌现理论。大语言模型的涌现能力能否在某个形式框架内被预测和解释，还是说它本质上是一种理论无法预先捕捉的经验现象？

**自指推理的能力边界**：当一个 AI 系统推理自己的推理过程时，它能发现哪些关于自身的真命题，又必然会从内部看不见哪些边界？这不仅是一个哲学问题，而是一个关于 AI 安全与可解释性的实际问题——一个无法推理自身极限的系统，会在什么情况下用自信的错误替代诚实的不确定性？

**MP 游戏留下的动力学缺口**：如果证明序列是一条轨道，那么不动点只是“停止”的名字，而不是“停在正确地方”的保证。第12章用 KL 能量面和压缩映射回答了“能量是什么、为什么递减”；第23章接着回答“收敛得多快、这个速率如何随规模变化”。逻辑语言到此为止，后面交给动力学。

## 思考题

**★ 热身**

Curry-Howard 对应的核心是：命题对应类型，证明对应程序。对以下每个逻辑命题，写出它在类型论中对应的类型（使用函数类型 $\to$、积类型 $\times$ 以及和类型 $+$）。

1. $A \to A$（同一律）
2. $A \to (B \to A)$（弱化）
3. $A \land B \to A$（合取消去）
4. $A \to A \lor B$（析取引入）

对第1条，写出一个“居住”在这个类型中的具体程序（函数），并验证它所对应的确实是“$A \to A$ 的一个证明”。

---

**★★ 推导**

1. **不动点展开**：$Y$ 组合子满足 $Y\,f = f\,(Y\,f)$。手工展开 $Y\,(\lambda x.\, \text{if } x = 0 \text{ then } 1 \text{ else } x \times (x-1))$ 的前三步（把这读作阶乘函数的递归定义）。追踪展开过程，并清楚解释 $Y$ 是如何“创造”递归的。

2. **哥德尔句与 Y 组合子**：哥德尔句 $G$ 说“我不可证”；$Y\,f$ 满足 $Y\,f = f\,(Y\,f)$。两者都是自指构造，但结果不同：$G$ 导致不可判定性，$Y\,f$ 导致无限循环（或递归展开）。列出它们在以下方面的异同：(1) 自指的机制；(2) 自指的后果；(3) 自指被“解决”的方式（如果有的话）。

---

**★★★ 挑战**

依赖类型系统（如 Martin-Löf 类型论）把“$\forall x.\, P(x)$”对应为 $\Pi$-类型：一个对每个 $x$ 都返回 $P(x)$ 的证明的函数。

考虑这个命题：“对所有自然数 $n$，$n$ 的后继不等于 $0$”，即 $\forall n \in \mathbb{N}.\, S(n) \neq 0$。

1. 在依赖类型论中，这个命题对应什么类型？用 $\Pi$-类型的语言写出来。
2. 这个命题的“证明”（即居住在这个类型中的程序）是什么样子？它接受什么输入，返回什么？
3. 现在考虑：类型检查（验证一个程序具有给定类型）等价于验证一个证明。这个验证操作是可判定的吗？（提示：依赖类型使类型检查变得更难——与简单类型系统相比，复杂度如何变化？）

第3个问题触及依赖类型系统的实际极限：功能越强大，类型检查的代价越高；某些依赖类型系统的类型检查甚至是不可判定的——这又是贯穿全书的律令“越强大，代价越高”的一次体现。

第3个问题没有标准答案。它是下卷在技术层面提出的最后一个开放问题——边界处的形式工具开始触及那些超出形式化范围的问题。在那个边界上，逻辑与直觉、证明与猜想、形式与意义，以一种我们尚未完全理解的方式彼此纠缠。全书的最终回答在第24章。
